# 前后端功能匹配核对

核对对象：`03-前端静态页面设计.html` 中的页面区域/动作，与 `02-后端接口文档.md` 中的接口。结果：所有页面动作均有后端契约；所有面向采购专员和主管的业务接口均有界面承载。管理员主数据维护属于独立管理页，已在接口文档提供，静态工作台不重复展示。

|前端功能|对应接口|核对结果|
|---|---|---|
|新建、切换、恢复草稿及自动保存|`POST/GET /drafts`、`GET/PATCH /drafts/{id}`|匹配|
|AI 整理、追问及显示异步结果|`POST /drafts/{id}/ai-extractions`、`GET /drafts/{id}/ai-jobs/{jobId}`|匹配|
|编辑并确认/撤销字段|`PATCH /drafts/{id}`、`POST/DELETE .../fields/{fieldName}/confirm`|匹配|
|上传附件、显示解析成功/失败、重新解析|`POST/GET .../attachments`、`POST .../parse`|匹配|
|搜索并选择物料、供应商|`GET /materials`、`GET /suppliers`、两个 selection 接口|匹配|
|查看并引用历史采购|`GET /purchase-applications/history`、`POST /history-references`|匹配|
|运行校验和疑似重复提醒|`POST /validation`、`GET /duplicate-candidates`|匹配|
|二次确认提交、重复请求安全返回|`POST /submit` + `Idempotency-Key`|匹配|
|正式申请详情、原始输入、附件、审计记录|`GET /purchase-applications/{id}`|匹配|
|主管通过/退回|`POST /purchase-applications/{id}/review`|匹配|

## 结论与实现提示

页面中的“待确认”“附件来源”“解析失败”“重复提醒”和“主管退回”均不是纯视觉状态，须直接使用对应 API 返回的数据。前端应以草稿 ID、`expectedVersion` 和 AI `jobId` 绑定状态；提交请求每次生成并复用同一 `Idempotency-Key` 直到收到确定结果。这样可覆盖页面切换导致的旧 AI 结果、并发编辑和重复提交三类关键边界。
