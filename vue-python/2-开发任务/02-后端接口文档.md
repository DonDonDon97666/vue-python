# 场景 1 后端接口文档（Python 3）

## 约定

- 基础路径：`/api/v1`；JSON 使用 `camelCase`。
- 除登录外均需要 Bearer Token。后端从令牌识别用户与角色，禁止由客户端传入他人 `userId`。
- 响应成功格式：`{ "data": ... }`；失败格式：`{ "error": { "code": "...", "message": "...", "fieldErrors": [] } }`。
- 草稿字段统一为 `{value, source, confirmed, updatedAt}`；`source` 取 `USER`、`AI`、`ATTACHMENT`、`HISTORY`。
- 所有上传、AI 解析和提交的异步状态均可由草稿详情恢复。

## 草稿与 AI

|方法与路径|用途|请求要点|返回要点|
|---|---|---|---|
|`POST /drafts`|新建草稿|`rawText`（选填）、`fields`（可不完整，含 material/specification/quantity/unit/expectedDeliveryDate/purpose/preferredBrand/preferredSupplier）|草稿 `id`、`status=DRAFT`、`version`、`updatedAt`|
|`GET /drafts`|我的采购草稿/已提交记录列表|`status=DRAFT|SUBMITTED`、`page`（默认 1）、`pageSize`（默认 20）|`items`、`total`、`page`、`pageSize`；仅返回当前用户的数据，按最后更新时间倒序|
|`GET /drafts/{id}`|加载完整草稿|—|字段、消息、附件、候选、确认和提交状态|
|`PATCH /drafts/{id}`|编辑原文或结构化字段|`rawText`、`fields`、`expectedVersion`|更新后的草稿版本；版本不一致时返回 `DRAFT_VERSION_CONFLICT`|
|`POST /drafts/{id}/ai-extractions`|请求 AI 提取/追问|`message`, `clientRequestId`, `expectedVersion`|当前开发版本同步返回 `jobId`、`status=SUCCEEDED`、`fields`、`missingFields`、`ambiguities`；所有字段均为未确认候选|
|`GET /drafts/{id}/ai-jobs/{jobId}`|获取 AI 任务状态|—|为后续异步化预留；生产中可返回 `PROCESSING/SUCCEEDED/FAILED`、建议和追问|
|`POST /drafts/{id}/fields/{fieldName}/confirm`|确认某字段|`value`, `sourceRef?`, `expectedVersion`|已确认字段与新版本|
|`DELETE /drafts/{id}/fields/{fieldName}/confirm`|撤销确认|`expectedVersion`|未确认字段与新版本|

`POST /ai-extractions` 失败时返回或最终任务状态为 `AI_TIMEOUT`、`AI_UNAVAILABLE`、`AI_INVALID_OUTPUT`，不修改已确认字段。服务端用 `draftId + clientRequestId` 去重，并以任务创建时版本校验结果，避免旧结果覆盖新编辑。

## 附件、主数据、历史参考

|方法与路径|用途|请求/返回要点|
|---|---|---|
|`POST /drafts/{id}/attachments`|上传附件|`multipart/form-data:file`；返回附件 ID、文件名、`UPLOADED`|
|`GET /drafts/{id}/attachments`|附件列表|返回状态、提取结果、失败原因、下载地址|
|`POST /drafts/{id}/attachments/{attachmentId}/parse`|重试解析|返回解析 `jobId`|
|`GET /materials?keyword=&active=true`|物料候选|仅返回当前有效物料：`id/code/name/specification/brand`|
|`GET /suppliers?keyword=&active=true`|供应商候选|仅返回当前有效供应商：`id/code/name/contact`|
|`POST /drafts/{id}/material-selection`|确认物料|`materialId`, `expectedVersion`；服务端二次校验有效性|
|`POST /drafts/{id}/supplier-selection`|确认供应商|`supplierId`, `expectedVersion`；服务端二次校验有效性|
|`GET /purchase-applications/history?keyword=&materialId=`|检索历史参考|只返回用户有权查看的申请及其可参考快照|
|`POST /drafts/{id}/history-references`|挂接历史参考|`applicationId`, `fieldNames`；生成未确认的 `HISTORY` 来源字段|

管理员接口：`GET/POST/PATCH /admin/materials` 与 `GET/POST/PATCH /admin/suppliers`。`PATCH` 可改变 `active`，仅管理员可调用；停用操作不篡改历史申请快照。

## 校验、提交、申请与复核

|方法与路径|用途|请求/返回要点|
|---|---|---|
|`POST /drafts/{id}/validation`|预校验|返回 `valid`、`fieldErrors`、`unconfirmedFields`、`inactiveSelections`|
|`GET /drafts/{id}/duplicate-candidates`|查询相似申请|返回近期候选及相似原因；不返回阻止标记|
|`POST /drafts/{id}/submit`|最终提交|Header `Idempotency-Key` 必填；Body `{finalConfirmed:true, expectedVersion}`；返回正式申请号或既有结果|
|`GET /purchase-applications`|申请列表|采购专员看本人；主管可按状态筛选|
|`GET /purchase-applications/{id}`|申请详情|最终快照、原始需求、附件、确认、审计日志、复核状态|
|`POST /purchase-applications/{id}/review`|主管复核/退回|`{action: APPROVE|RETURN, reason?}`；退回必须有原因|

`submit` 在一个事务内重验字段、确认状态和主数据有效性，写入 `Submission(draftId,idempotencyKey,applicationId)`、正式申请快照和审计日志。相同幂等键返回第一次创建的申请；不同幂等键但草稿已提交返回 `DRAFT_ALREADY_SUBMITTED` 及既有申请。

## 关键示例

```http
POST /api/v1/drafts/dft_01/submit
Authorization: Bearer <token>
Idempotency-Key: 42b2b2ef-4b40-4f40-ae70-88c0b9569d4c
Content-Type: application/json

{"finalConfirmed": true, "expectedVersion": 12}
```

```json
{"data":{"applicationId":"pa_20260903_001","applicationNo":"PR-20260903-001","status":"SUBMITTED"}}
```

校验失败（HTTP 422）示例：

```json
{"error":{"code":"VALIDATION_FAILED","message":"提交前校验未通过","fieldErrors":[{"field":"expectedDeliveryDate","message":"请选择未来交期"}],"unconfirmedFields":["specification"]}}
```
